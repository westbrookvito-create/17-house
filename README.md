# 17 House — Telegram-бот + Mini App

Полностью рабочий Telegram-бот с мини-приложением для закрытого клуба 17 House:
визитка участника, каталог футболок, бонусная программа, заявки на покупку и
админ-панель — всё внутри Telegram.

## Структура репозитория

```
bot/     — Node.js + Telegraf + Express API + SQLite. Деплой на Railway.
webapp/  — React (Vite) мини-приложение в дизайне концепта. Деплой на Vercel.
```

Как это работает: `webapp` — статический сайт, который Telegram открывает
внутри бота как Mini App. Он обращается к REST API, который поднимает `bot`
(тот же процесс, что держит соединение с Telegram и присылает уведомления
администратору). Вся админка (товары, подтверждение оплаты) делается через
переписку с ботом в Telegram — отдельной веб-панели нет.

---

## 1. Настройка бота в @BotFather

1. Откройте [@BotFather](https://t.me/BotFather), выполните `/newbot` (если бота ещё нет) и сохраните токен.
2. Включите Mini App для бота: `/newapp` → выберите бота → укажите название,
   описание, картинку и **Web App URL** (это будет URL вашего Vercel-сайта,
   его вы получите на шаге 3 — можно вернуться и обновить командой `/myapps`).
3. Чтобы кнопка открытия приложения появлялась в самом чате, ничего
   дополнительно делать не нужно — бот сам присылает inline-кнопку
   «🏛 Открыть 17 House» по команде `/start` (см. `bot/src/bot/keyboards.js`).
4. Узнайте свой Telegram ID (например, через [@userinfobot](https://t.me/userinfobot))
   — он понадобится для `ADMIN_IDS`.

---

## 2. Деплой бэкенда бота (Railway)

1. Создайте новый проект на [Railway](https://railway.app), подключите этот
   репозиторий (или папку `bot/` как корень сервиса — в настройках сервиса
   укажите **Root Directory: `bot`**).
2. Добавьте переменные окружения (Settings → Variables), см. `bot/.env.example`:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от BotFather |
   | `ADMIN_IDS` | ваш Telegram ID (через запятую, если админов несколько) |
   | `WEBAPP_URL` | URL вашего Vercel-сайта (шаг 3) |
   | `CORS_ORIGIN` | тот же URL Vercel-сайта |
   | `CLUB_NAME` | `17 House` |
   | `BONUS_THRESHOLD` | `3` |
   | `BONUS_PERCENT` | `10` |
   | `CLUB_CHANNEL_URL` | ссылка-приглашение в закрытый канал (опционально) |

   `PORT` и `DB_PATH` можно не задавать — Railway подставит порт сам, а база
   SQLite будет лежать в volume контейнера (`bot/data/17house.db`). Для
   надёжности подключите Railway **Volume** на путь `/app/data`, чтобы данные
   не терялись при передеплое.
3. Railway автоматически соберёт и запустит `node src/index.js` (см.
   `bot/railway.json` / `bot/Procfile`). Бот работает через long polling —
   отдельно настраивать webhook не нужно.
4. После деплоя откройте `https://<ваш-сервис>.up.railway.app/health` —
   должен вернуться `{"ok":true,"club":"17 House"}`.

---

## 3. Деплой мини-приложения (Vercel)

1. Создайте проект на [Vercel](https://vercel.com) → **Add New → Project** →
   импортируйте этот репозиторий из GitHub.
2. На экране настроек укажите **Root Directory: `webapp`** — Vercel сам
   распознает Vite-проект и подставит `npm run build` / `dist` (это же
   продублировано в `webapp/vercel.json`, включая rewrite всех путей на
   `index.html`, необходимый для роутинга мини-аппа).
3. Добавьте переменную окружения проекта (Settings → Environment Variables):

   | Переменная | Значение |
   |---|---|
   | `VITE_API_URL` | URL бэкенда с Railway (без слэша на конце), например `https://17house-bot-production.up.railway.app` |

4. Задеплойте сайт, скопируйте его URL (вида `https://<проект>.vercel.app`)
   и вставьте в переменную `WEBAPP_URL` бэкенда на Railway (шаг 2) — после
   этого передеплойте бэкенд, чтобы кнопка в боте вела на актуальный адрес.
5. Обновите Web App URL в `@BotFather` (`/myapps` → ваше приложение →
   Edit Web App URL) тем же адресом Vercel.

## 4. Как пользоваться ботом

### Обычный участник
- `/start` — приветствие и кнопка «Открыть 17 House».
- `/size` (или кнопка «📏 Узнать размер» под приветствием) — присылает 2 фото
  таблицы размеров (`webapp/public/size-chart-1.jpg` и `size-chart-2.jpg`,
  раздаются вместе с мини-аппом так же, как `hero.jpg`).
- Внутри мини-аппа: Главная → Футболки → Визитка клуба → Бонусы → Профиль
  (доступны через кнопку ☰ на главной или свайпом по разделам).
- Покупка футболки: у каждого товара в каталоге — название, галерея фото
  (свайп, если фото несколько) и размеры. Отдельного выбора цвета нет —
  каждый цвет/вариант оформляется как самостоятельный товар в каталоге
  (например «House Every Weekend Tee — Navy» и «... — Beige» — два разных
  товара). Выбор размера → «Купить футболку» → заявка уходит администратору
  в Telegram, статус заказа появится, когда админ подтвердит оплату (бот сам
  пришлёт сообщение в чат).
- Визитка клуба доступна из Профиля (строка «Визитка клуба») и с кнопки
  «Войти в клуб» на главной.

### Администратор (для тех, чей Telegram ID указан в `ADMIN_IDS`)
- `/admin` — открывает панель:
  - **➕ Добавить товар** — пошаговый диалог: название → описание → цена →
    размеры → фото товара. Можно прислать несколько фото подряд (бот
    подтверждает каждое и подсказывает рекомендуемый размер: квадрат/4:5 от
    1200×1200 px, JPEG/PNG до 5 МБ) — когда фото достаточно, отправьте
    `/done` → предпросмотр → «✅ Опубликовать». Каждый цвет/вариант товара —
    отдельный проход этого диалога, отдельная карточка в каталоге.
  - **📦 Товары** — список товаров, у каждого: изменить название/цену/описание/
    размеры, заменить фото (тот же порядок: несколько фото → `/done`),
    скрыть/показать в каталоге, удалить.
  - **🧾 Заказы** — открывает фильтр по статусу (Все / Ожидают оплаты /
    Оплачены / Отправлены / Получены / Отменены), затем по способу доставки
    (Все / Яндекс Доставка / СДЭК), и показывает **абсолютно все заказы**,
    когда-либо оформленные в клубе, с полной карточкой каждого: товар,
    размер, сумма, способ доставки, ФИО и телефон получателя, адрес ПВЗ и
    какие именно реквизиты были показаны клиенту.
  - Карточка заказа никогда не «стирается» при смене статуса — она
    перерисовывается заново с полными деталями и новыми доступными кнопками:
    `⏳ Ожидает оплаты` → (✅ Подтвердить / ❌ Отменить) → `✅ Оплачен` →
    (📦 Отметить отправленным) → `📦 Отправлен` → (📬 Отметить полученным) →
    `📬 Получен`. Каждый переход шлёт покупателю соответствующее уведомление.
  - `/cancel` — отменить текущий шаг диалога (например, добавление товара).

При оформлении заказа в мини-аппе покупатель выбирает доставку (Яндекс
Доставка / СДЭК), указывает ФИО (как в переводе), телефон и адрес ПВЗ, после
чего ему показывается один из трёх реквизитов для оплаты, выбранный случайно
(настраивается через `PAYMENT_REQUISITES` в `.env`, по умолчанию — три
номера на Альфа-банк). Вся эта информация всегда доступна админу в карточке
заказа.

Бонус: после 3 оплаченных футболок участнику автоматически начисляется
скидка 10% на все следующие заказы (пороги настраиваются через
`BONUS_THRESHOLD` / `BONUS_PERCENT`).

## 5. Локальная разработка

```bash
# бэкенд
cd bot
cp .env.example .env   # заполните BOT_TOKEN и ADMIN_IDS
npm install
npm test                # сквозная проверка бота и API без реального Telegram
npm run dev             # поднимет бота (polling) и API на :3000

# мини-апп (в отдельном терминале)
cd webapp
cp .env.example .env.local   # VITE_API_URL=http://localhost:3000
npm install
npm run dev              # http://localhost:5173
```

`npm test` (в `bot/`) прогоняет весь бэкенд через настоящий диспетчер
обновлений Telegraf на одноразовой SQLite-базе, без сети и без реального
токена: регистрация участника и выдача номера карты, полный визард
добавления товара (название → фото), редактирование/скрытие/удаление
товара, создание и подтверждение/отмена заказа, уведомления админу и
покупателю, разблокировка визитки клуба и бонусной скидки после первой и
третьей покупки, пересылка сообщений менеджеру. Стоит запускать после любых
изменений в `bot/src`.

Мини-апп проверяет подпись Telegram `initData`, поэтому при открытии просто
в браузере запросы к API будут отклонены (401). Для локальной отладки вне
Telegram включите в `bot/.env`:

```
DEV_ALLOW_INSECURE=1
```

и добавьте в `webapp/.env.local`:

```
VITE_DEBUG_USER_ID=1
```

— тогда фронтенд будет подставлять тестового пользователя с этим Telegram ID.
**Не включайте `DEV_ALLOW_INSECURE` в продакшене.**

## 6. Что можно донастроить дальше

- Реальная онлайн-оплата (сейчас — заявка + ручное подтверждение админом в Telegram, как и было запрошено).

- Пуш-уведомления о новых событиях клуба через рассылку ботом.
